# 一人公司的 AI 技术栈：Agent、RAG、MCP、Skills

## 四个核心概念
- **大模型（LLM）**：负责理解和生成，像“大脑”。选择时看能力、价格、上下文长度和数据合规。
- **RAG（检索增强生成）**：把自己的资料切块建索引，提问时先检索相关片段再交给模型回答，让 AI 懂你的业务、减少编造，并能给出出处。适合产品资料、SOP、FAQ、合同条款等。资料更新后重建索引即可，不用重新训练模型。
- **MCP（Model Context Protocol，模型上下文协议）**：Anthropic 于 2024 年 11 月开源的开放协议，让 AI 应用以统一方式连接外部工具和数据源。写一次 MCP Server，Claude、Cursor 等支持 MCP 的客户端都能调用。可以把它理解为 AI 的“USB-C 接口”。
- **Agent Skills（技能）**：一个文件夹，里面有 SKILL.md（说明何时使用、怎么做）以及脚本和资源。Agent 在需要时才加载完整内容，适合沉淀可复用的工作流程。
- **Agent（智能体）**：能自主规划、调用工具、多步执行任务的 AI 系统 = 模型 + 工具（MCP）+ 知识（RAG）+ 流程（Skills）+ 记忆。

## 典型组合
- 客服/销售助理：RAG（产品知识）+ 邮件/CRM 工具 + 话术 Skill。
- 内容工厂：选题 Agent → 写作 Agent → 审核 → 自动发布工作流。
- 报价助理：RAG（价格表、条款）+ 计算脚本 + PI 模板。

## 自动化工具
- **n8n**（可自托管）、**Make**、**Zapier**：无代码/低代码工作流，把表单、邮件、表格、AI 调用串起来。
- **Python 脚本 + 定时任务**：灵活、成本低，适合有一定技术能力的人。

## 选型原则
1. 先用现成工具验证，再自己开发。
2. 模型可替换：业务逻辑不要绑死在某一家模型上。
3. 数据是资产：客户数据、知识库要自己掌握并备份。
4. 关键动作（付款、对外发送）保留人工确认。
